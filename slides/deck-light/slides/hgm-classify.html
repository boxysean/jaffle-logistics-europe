select
    chunk_id,
    {{ dbt_context_engineering.classify(
        'chunk_text',
        prompt = dbt_context_engineering.prompt(
            'jaffle_content_type', 'v1'),
        output_schema = dbt_context_engineering.schema_def(
            'jaffle_content_type', 'v1')
    ) }} as content_type
from {{ ref('incident_reports_hashed') }}
Step four, classify, side by side with embed. A model reads each passage and picks one label from a fixed list of six. The model on the right names the prompt and its output schema by version, jaffle_content_type v1, so a change to the prompt is a change you can see in git, and the schema keeps the answer to the six allowed labels. IR-9001's first two passages come back weather_disruption. The third, "Reviewed with dispatch.", comes back routine_status, which is right: it says nothing about the storm. Across the whole knowledge base, 548 of the 2,708 rows are weather_disruption, so a search filtered on that label looks at 548 rows, not 2,708, before the vector math even starts.
