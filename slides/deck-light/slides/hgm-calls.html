Start with the question, out loud: what happened in 2025 Q1 that caused on-time to go down? Click through: the boxes light in a snake. The agent splits it in two. The number goes to the semantic layer over MCP: query_metrics, and the agent picks the governed metric on_time_rate, by quarter, then Q1 by origin city. Back comes 90.33% for Q1, the low quarter, and Paris in January at 56.60%. The cause goes to the context layer: a search over the knowledge base. The search embeds the query with the same model that embedded the passages, then scores every passage by cosine similarity: how closely its 1,024 numbers point the same way as the query's, 1.0 being identical. Filtered to weather_disruption, the top passage is IR-9001 at 0.779: the jackknife in the storm. The agent assembles the two into one answer and cites both: the metric and the report. If asked: the search query on the slide, "truck accident during the Paris winter storm" in the build, is the one stored in the search model, so the scores are real; a live agent would phrase its own. The agent itself is a design, not a running system; the two calls and their results are real.
