THE dbt MODEL, CONDENSED 
-- int_incident_reports_documents.sql
select
    r.report_id,
    s.client_id,
    ai_parse_document(r.content) as body,
    r.filed_at as artifact_ts,
    'jaffle_logistics://incident_report/'
        || r.report_id as citation_url
from {{ ref('stg_incident_reports') }} r
left join {{ ref('stg_shipments') }} s
    on r.shipment_id = s.shipment_id

Step one, parse. Read left to right: the file, the model, the row it writes. Picture the incident system exporting each report as a PDF: a form with a field block and four sections. The model in the middle turns the file into text with Databricks' ai_parse_document (Snowflake and BigQuery have their own), and joins the report to its shipment, which gives it an account, CLI-0042 Jaffle Werke, and a citation back to IR-9001. Parse is an AI call, so it costs money, once per file. Be straight with the room if asked: in this demo the reports arrive as text already, so the real int_incident_reports_documents has no parse call; it restores line breaks in staging and does the join, which is otherwise the model you see.
