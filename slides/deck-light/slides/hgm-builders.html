The context layer, built like the rest of your governed data
WHY IT'S BETTER
✓Built by the same team who builds the governed data
✓Tested, with lineage, re-usable
✓Efficient: build the right context once
✓Adapts as the business adapts
✓Fast to build with AI development
Why build it this way? it is built by the same team who already builds the governed data, so the context and the numbers come from one place. Like any dbt model it is tested, has lineage, and is re-usable by every agent and tool. It is efficient: the right context is built once, not re-assembled in every prompt. It adapts as the business adapts, because a change is a pull request like any other. And with AI development, the skills and a coding agent, it is fast to build.
