Now the part people always ask about: the embeddings. Six: incident_reports_embed calls embed() on each passage, here Databricks' gte-large-en, and gets back 1,024 numbers per passage. It is incremental, keyed on the hash from the previous slide, so a passage whose text has not changed is not embedded, or paid for, again; only a new embedding model re-embeds the lot. Seven: incident_reports_classify asks a model for one label per passage, from a versioned prompt, jaffle_content_type v1. The first two passages of IR-9001 come back weather_disruption; the last one, "Reviewed with dispatch.", comes back routine_status, which is right. Eight: knowledge_base unions seven sources into one shape, 2,708 rows in all, 715 of them incident passages. Nine: search embeds the question and finds the nearest rows; IR-9001's first passage comes first at 0.779. Only six and seven, and the query embedding in nine, call an AI function, and they only run when the build is told to: ai_functions_enabled is off by default.
